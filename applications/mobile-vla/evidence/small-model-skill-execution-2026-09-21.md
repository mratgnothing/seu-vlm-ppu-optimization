# 端侧小模型 Skill 调用与真实执行测试

日期：2026-09-21\
模型：Qwen3.5-2B-MNN（MNN 4-bit，手机 CPU）\
设备：Xiaomi 17（Android 16）

## 结论

端侧 2B 模型能够在“单意图、单 Skill”的约束下，正确选择电话呼叫、微信消息和微信视频呼叫三个 Skill，并填写授权别名、固定消息 ID 和五秒时限。三个通过安全门的调用随后都完成了真实手机动作。

这次闭环中的模型职责是理解自然语言并选择 Skill；Skill 执行器负责把匿名别名解析为会话外绑定、验证目标与参数、操作手机和执行后观察。模型没有获得真实电话号码、微信账号、任意消息文本或任意坐标。

## 规划协议测试

MNN Chat 0.8.3 的 OpenAI 兼容接口在本轮没有按标准 `tools` 字段返回原生 `tool_calls`。首次复杂请求中，模型理解了大部分任务，但发生了 Skill 名改写、结构不合规和解释性输出，均被安全门拒绝，没有触发外部动作。

将任务改为“单意图、单 Skill、执行后再规划下一步”后，结果如下：

| 端侧规划任务 | 结果 | 端侧规划耗时 | 安全门 |
|---|---|---:|---|
| 呼叫已绑定联系人，最多 5 秒 | 通过 | 约 3.89 秒 | 精确 Skill 名、别名和时限通过 |
| 发送预批准微信测试消息 | 通过 | 约 3.78 秒 | 精确 Skill 名、别名和消息 ID 通过 |
| 发起微信视频呼叫，最多 5 秒 | 通过 | 约 3.82 秒 | 精确 Skill 名、别名和时限通过 |

脱敏后的原始规划结果分别保存在：

- `evidence/small-model-plan-call.json`
- `evidence/small-model-plan-message.json`
- `evidence/small-model-plan-video.json`

## 真实执行结果

| Skill | 结果 | 执行保护 |
|---|---|---|
| `call_bound_contact` | 成功进入真实拨号状态，5 秒后结束 | 拨号界面完整号码与会话外绑定逐位一致后才点击 SIM1 |
| `send_wechat_message` | 成功发送固定测试说明消息 | 只接受固定 `message_id`；在已验证绑定会话中执行 |
| `start_wechat_video_call` | 成功进入真实视频呼叫等待状态，5 秒后结束 | 必须承接同一已验证会话；只允许固定时限 |

## 已实现的 Skill 约束

Skill 注册表位于 `configs/communication_skills.json`，端侧规划器位于 `src/communication_skill_agent.py`。注册表具有以下约束：

- 联系人参数只能是匿名别名 `authorized_test_contact`；
- 电话号码与微信搜索标识保留在会话外的临时绑定中；
- 消息内容由固定 `message_id` 映射，模型不能自由生成并发送文本；
- 呼叫和视频等待时长固定为 5 秒；
- 每次调用都需要当次授权，且一次性授权文件在执行后删除；
- 未知 Skill、多余参数、别名变化、顺序变化或输出格式错误都会拒绝执行。

## 安全收尾

- 模型规划期间 Wi-Fi 和移动数据均关闭，API 只绑定手机本机 `127.0.0.1:8080`。
- API 密钥从应用私有调试配置中只读取得，未打印、未写入项目文件。
- 微信联网执行前已停止 MNN；模型服务与微信网络访问没有同时开放。
- 测试结束后 API 开关为关闭、MNN 进程不存在、ADB 转发为空。
- Wi-Fi 恢复，移动数据保持原有关闭状态，手机返回桌面。
- 临时聊天截图、UI 转储和一次性授权文件均已删除。

## 能力边界

本轮证明了“小模型可作为受限 Skill 路由器”，还没有证明它能可靠生成多步骤原生工具调用。标准 `tools` 字段兼容性和复杂规划稳定性仍需改进。当前推荐的产品结构是：

```text
用户意图
  → 端侧小模型选择一个 Skill
  → 确定性安全门
  → 绑定解析与 Skill 执行
  → 执行后观察
  → 再决定下一 Skill
```

对联系人、支付、验证码、删除和隐私分享等高风险动作，不能把模型的一次长计划直接转换成连续点击。
