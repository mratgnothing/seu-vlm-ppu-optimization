# 授权通信能力真机冒烟测试

日期：2026-09-21\
设备：Xiaomi 17（Android 16）\
范围：一次授权电话号码呼叫、一次授权微信好友文本消息、一次授权微信视频呼叫，以及两张当前界面截图的端侧视觉识别。

## 结论

手机控制链路可以完成拨号、微信文本发送和微信视频呼叫等基础动作，但当前 2B 端侧视觉模型不能独立承担收件人身份确认。测试中，模型准确识别了拨号界面的 11 位号码，却把微信聊天标题中的三字姓名识别成另一个姓名。涉及联系人、号码、消息发送或呼叫的动作，必须在模型之外增加确定性的身份校验与最终确认。

## 实际执行结果

| 项目 | 结果 | 观察 |
|---|---|---|
| 电话呼叫 | 通过 | 在拨号前核对完整授权号码，进入真实“正在拨号”状态，约 10 秒后主动挂断。 |
| 微信文本消息 | 通过 | 通过搜索进入唯一目标好友会话，核对会话标题后发送测试说明消息。 |
| 微信视频呼叫 | 通过 | 进入真实等待接听页面，数秒后结束；对方随后拒绝邀请。 |
| 小模型识别拨号号码 | 通过 | 返回值与授权号码 11 位完全一致；约 2.68 秒，输入 202 tokens、输出 12 tokens。 |
| 小模型识别微信联系人 | 失败 | 返回了不同的三字姓名；约 2.89 秒，输入 207 tokens、输出 4 tokens。 |

## 能力边界

- 真实外部动作由明确授权、确定性目标核对和逐步界面观察共同约束；不是让小模型自主挑选联系人后直接执行。
- 本次证明“控制链路能够完成动作”，同时也证明“仅凭小模型截图识别不能安全放权”。
- 数字界面较清晰时，2B 模型已表现出可用的局部视觉能力；小字号中文姓名、相似字和身份绑定仍是明显短板。
- 在微信这类 UI 控件树信息很少的应用里，坐标点击可以完成演示，但产品化必须结合联系人稳定 ID、OCR/无障碍语义、页面状态机和二次确认。

## 数据安全措施

- 未遍历相册，未导出通讯录，也未读取与任务无关的联系人；授权能力按最小必要范围使用。
- 模型视觉请求仅经手机本机回环 API 执行；推理期间 Wi-Fi 与移动数据均关闭。
- 截图仅用于当前步骤识别，未写入项目证据；本机临时截图和 UI 转储均已删除。
- 证据只记录脱敏目标，不包含完整电话号码、联系人全名、聊天内容或相机画面。
- 测试结束后，MNN API 服务已关闭、MNN 进程已停止、ADB 端口转发为空、Wi-Fi 恢复、移动数据保持原有关闭状态，手机返回桌面。

## 对原型设计的直接要求

1. 收件人身份必须由通讯录稳定 ID 或经过验证的唯一账号绑定，禁止只依赖视觉读名。
2. 拨号、发送消息、视频呼叫均显示“对象 + 动作 + 内容/类型”的最终确认卡。
3. 模型只输出候选意图；安全门负责白名单、身份一致性、风险等级和执行许可。
4. 视觉/OCR 与结构化信息不一致时立即停止，并把选择权交还用户。
5. 保存脱敏审计事件，不保存原始相册、聊天截图、通讯录快照或通话预览。
