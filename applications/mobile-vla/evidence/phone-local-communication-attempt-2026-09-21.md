# 手机本地通信闭环追加验收

日期：2026-09-21

## 验收范围

本轮在用户明确的一次性授权范围内，依次验证电话、微信文本与微信视频三个通信动作。联系人和消息均通过本机私有绑定解析；公开证据只保留匿名别名与消息 ID，不记录真实号码、联系人姓名、消息正文、API 密钥或含个人信息的截图。

执行链为：手机本地 Qwen3.5-2B-MNN 生成单一 Skill JSON，确定性安全门校验动作名和参数，Android 执行器核对私有绑定与当前界面，校验通过后才允许真实动作。任一模型输出、绑定或界面核验异常均按 fail-closed 停止。

## 结果

| 项目 | 模型规划 | 安全门与执行 | 最终结果 |
| --- | --- | --- | --- |
| 电话约 5 秒 | 严格返回 `call_bound_contact` | 参数门通过，拨号器进入真实通话；约 5 秒后挂断并回到系统拨号器 | PASS |
| 微信文本 | 曾在新启动的本地模型会话中严格返回 `send_wechat_message` | 切换到微信后聊天绑定指纹核验返回 `FAIL_CLOSED` | 未发送 |
| 微信视频约 5 秒 | 未进入执行阶段 | 前一项身份核验未通过，状态机停止后续外部动作 | 未启动 |

## 关键边界

- 电话成功证明了“本地模型选择 Skill → 确定性门 → 私有绑定 → 真实动作”的受限闭环；它不代表模型可以任意读取通讯录或自由拨号。
- 微信消息没有发送，微信视频没有启动。此前由电脑辅助完成的冒烟测试不能算作本轮 Android Agent 端到端通过。
- MNN Chat 0.8.3 在重复请求或前台应用切换后出现过请求阻塞、回显提示词或返回非 Skill 文本。运行脚本因此要求响应内容必须以唯一、完整、预期的 JSON Skill 开头，其他输出全部拒绝。
- 微信当前版本向 Accessibility 暴露的结构化节点不足；聊天身份需依赖私有绑定、Activity、截图指纹与本地视觉的联合核验。本轮应用切换后指纹桥接不稳定，安全门按设计停止，没有使用裸坐标绕过。

## 结论

本轮新增的可复现结论是：真实电话 Skill 已通过一次约 5 秒的授权验收；微信文本与微信视频仍是待解决项。后续应先修复 MNN 会话生命周期与微信绑定指纹的跨应用稳定性，再申请新的单次授权复测，不能复用本轮授权重复产生外部通信。
