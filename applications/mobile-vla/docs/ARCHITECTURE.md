# 架构与迭代边界

## 最小闭环

```text
语音/文字任务
  → Android 截图 + Accessibility 控件树
  → 个人关系、已验证工作流、安全规则检索
  → Qwen3.5-2B 生成结构化动作
  → 安全门（ACT / CLARIFY / HANDOFF）
  → ADB（实验）或 AccessibilityService（产品）执行
  → 获取下一状态并判定成功
  → 追加轨迹和用户反馈
```

## 两条运行路径

### 路径 A：立即可验证的端—边协同

手机负责截图、交互和执行，模型运行在电脑或 PPU 可信边缘节点。该路径用于尽快建立 GUI-VLA 闭环，并复用现有评测与 PPU 优化经验。

### 路径 B：Android 端侧模型

使用 MNN 4-bit Qwen3.5-2B 在手机本地完成视觉理解和短动作生成。首次试跑以 CPU 后端为基线，再根据设备和 MNN 支持情况验证 OpenCL/Vulkan/QNN/Hexagon。

PPU kernel 不能直接用于骁龙芯片。可迁移的是 Prefill/Decode 分离、GDN 快速路径、低比特权重、算子融合、持久缓存和精度护栏等方法。

## Skill 调用层

通信类任务优先使用高层 Skill，不让小模型直接生成电话、联系人或微信页面坐标。当前注册表提供：

- `call_bound_contact`：呼叫经过授权绑定的匿名联系人；
- `send_wechat_message`：发送固定消息 ID 对应的预批准文本；
- `start_wechat_video_call`：在已验证会话中发起限时视频呼叫。

端侧模型只看到匿名别名与受限枚举。真实号码、账号搜索标识和消息正文由确定性执行层在会话外解析。每次只允许一个 Skill，安全门校验通过并观察执行结果后，模型才能规划下一步。复杂多 Skill 输出、名称改写、多余参数和未知别名一律拒绝。

## 知识库的迭代机制

知识分成四层：

1. `entities`：联系人关系、称呼和首选渠道；
2. `episodes`：每次真实任务的不可变轨迹和结果；
3. `knowledge_proposals`：从多次轨迹总结出的候选工作流；
4. `workflow_cards`：经过人工审核后发布的可检索流程。

所有轨迹进入 SQLite 前都会进行递归脱敏：敏感字段名直接替换，手机号、身份证号、银行卡号和六位验证码按模式清除。知识提案除了至少三条成功证据，还要求该任务累计成功率不低于 80%。

更新流程：

```text
真实操作轨迹
  → 脱敏
  → 同类任务至少 3 次成功证据
  → 生成工作流提案
  → 人工审核风险、步骤和适用版本
  → 发布新版本
  → 旧版本保留并可回滚
```

“不断学习”在这里表示持续积累证据并发布新版本，不允许模型在一次交互后静默修改安全规则或已验证流程。

每次批准和回滚都会写入 `workflow_audit`。回滚只切换已保存版本的状态，不删除失败版本和历史证据。

## RAG 到执行约束

检索结果不能只作为提示词背景。人物关系和已验证流程会生成 `required_target_tokens`，例如 `陈小雨 + 女儿`。安全门先检查模型描述是否包含全部语义；真机执行时再从 Android `uiautomator` 控件树中寻找同时匹配这些语义的唯一节点，并使用节点中心坐标覆盖模型坐标。如果只检索到“陈小雨”且存在两个同名节点，执行器拒绝选择并要求澄清。

## 数据最小化

- 默认只保存结构化动作、页面状态摘要和成功判定。
- 截图需要显式开启保存，并在进入训练集前脱敏。
- 验证码、支付口令、身份证号、银行卡号和完整聊天内容不进入知识库。
- 人物关系采用本地 ID；导出演示数据时使用虚构身份。

## 评价指标

- 完整任务成功率、单步动作正确率、恢复成功率；
- 首动作延迟、单步推理时间、任务总耗时；
- 峰值内存、温升、电量和模型加载时间；
- 高风险动作拦截率、错误自动执行率、澄清触发准确率；
- 本地完成率和需要边缘节点接管的比例。
