## 1. 一句话结论

项目的前半段基础工作已经比较扎实：官方模型、公开集、Accuracy 基线、TTFT/Throughput 计时、CUDA Profile、基础优化、PPU SDK/编译链和提交候选包都已经建立。

当前真正的关键缺口不是继续在 RTX 4050 上做小幅优化，而是尽快完成：

**官方 v1.2 同步 → 私有 PAI/PPU 环境确认 → Qwen3.5-2B 真实 PPU baseline → PPU Profile → 针对性优化 → 重复复测 → 最终提交包与技术报告。**

时间已经进入冲刺阶段。仓库最后一次系统性状态更新停留在 2026-07-26，而赛事在 8 月已经进入私有 PPU 资源、v1.2 代码和统一环境评测阶段，因此接下来首先要消除这段“状态断层”。

## 2. 赛题目标与当前技术路线

赛道二的核心目标是在主办方指定的 **Qwen3.5-2B** 模型和 **平头哥真武 810E PPU** 环境上完成 VLM 推理优化。

我们当前的技术路线是：

1. **先守住 Accuracy**：任何性能优化都必须有精度回归护栏，不接受通过破坏输出正确性换取速度。
2. **再优化 TTFT 与 Throughput**：分别关注首 token 延迟和持续生成吞吐。
3. **先建立真实 baseline，再做单变量优化**：每项优化都要能追溯到代码提交、环境和实验记录。
4. **以真实 PPU Profile 为依据决定优化方向**：本地 RTX 4050 Profile 只用于前期定位和方法验证，不能直接等同于 PPU 瓶颈。
5. **最终交付以“主办方统一环境可复现”为标准**：不是“本机能跑”就算完成。

现阶段不建议把主要精力投入到未经主办方确认的激进量化、剪枝或权重变换。优先完成兼容性、真实运行、稳定性和可复现性，再根据正式规则决定是否进入更激进路线。

这意味着 Accuracy 的权重很高。除非主办方后续规则发生变化，否则不值得为了较小的速度收益明显牺牲 Accuracy。

## 4. 仓库当前已经完成什么

截至仓库现有可复现记录，主要成果如下。

### 4.1 官方模型和数据基线

- 官方模型：`Qwen/Qwen3.5-2B`
- 固定 revision：`15852e8c16360a2fea060d615a32b45270f8a8fc`
- 主权重 SHA-256：`aa33250c4fc64891ddfaba3a314fd9542ea371843c387178b425fbcc5ed680b1`
- 已在 RTX 4050 Laptop GPU 6 GB 上完成 BF16 纯 GPU 加载。
- MMBench 中文/英文公开集各 4029 条已经完成结构、答案域和完整性检查。

### 4.2 完整 Accuracy

当前完整公开集结果：

| 数据集 | Accuracy | 正确数 / 总数 |
|---|---:|---:|
| 中文 MMBench | 83.94% | 3382 / 4029 |
| 英文 MMBench | 79.75% | 3213 / 4029 |

中英文完整集均进行了分块、题号集合和答案域审计。

英文原始结果曾出现一条因输出格式截断导致无法解析的样本。仓库对 Markdown 选项和显式结论做了通用规范化，完整异常分块复测后只恢复这一条，不存在按题号或答案硬编码修补。

### 4.3 TTFT / Throughput 基线和 O1 优化

当前正式性能对比使用固定前 20 条样本、三次重复实验和首 token 计时口径。

O1 为 `torch.inference_mode()`，在答案、token 数和 Accuracy 不变的前提下：

| 语言 | TTFT 改善 | Throughput 改善 |
|---|---:|---:|
| 中文 | 8.25% | 8.82% |
| 英文 | 10.22% | 6.37% |

这说明当前评测、计时和回归体系是可工作的，但这些数字仍然只是 **RTX 4050 本地结果**，不能当作 PPU 最终性能。

### 4.4 CUDA Profile

本地单样本 CUDA profiler 显示：

- GEMV/GEMM 占 self CUDA time 约 **86.18%**；
- elementwise / copy 调用较多；
- peak allocated / reserved 约为 **4.19 / 4.21 GiB**。

这为前期判断 decode 侧矩阵运算热点提供了依据，并已准备三组关键 BF16 GEMV PPU 微基准。

但下一阶段优化优先级必须以 **真实 PPU Profile** 为准。GPU 上的热点只能作为候选方向。

### 4.5 PPU 基础工具链

已在共享 PPU 环境完成：

- 真武 810E 设备识别；
- SDK / Driver / HGGC 核验；
- 官方 `vectorAdd` 编译和运行通过；
- PPU-vLLM 源码与 Qwen3.5 架构兼容性调查；
- Qwen3.5 GDN、MLP、全注意力、视觉层关键尺寸梳理；
- BF16 GEMV 参考微基准准备。

这些只能证明 **基础 PPU SDK / 编译 / kernel 链可用**。

目前仓库没有证据表明已经完成：

> Qwen3.5-2B 在目标私有 PPU 上真实加载并产生有效 Accuracy、TTFT、Throughput。

因此目前不能写“PPU 部署完成”。

### 4.6 工程和交付基础

仓库已经包含：

- 无模型接口测试；

8. 继续做本地 RTX 4050 小优化。

如果时间发生冲突，应该优先牺牲“报告美化”和“本地小优化”，不能牺牲真实 PPU 闭环。

---

## 10. 当前项目完成度判断

可以把项目现状理解为：

- **模型/数据/本地 baseline：成熟**；
- **Accuracy 与基本性能评测：成熟**；
- **本地优化方法和 Profile：已建立**；
- **PPU 工具链基础：已验证**；
- **真实 PPU 模型部署：未闭环**；
- **PPU 性能优化：尚未形成正式结果**；
- **官方 v1.2 同步：待完成**；
- **最终提交与技术报告：有基础，但必须等待 PPU 结果后收敛**。

因此我们现在不是“重新开始”，而是进入最关键、也最需要快速推进的后半程。

**未来几天的判断标准只有一个：每天是否在缩短“真实 PPU 可复现最终候选”与当前代码之间的距离。**
