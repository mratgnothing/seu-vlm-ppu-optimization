# PPU 视觉 Token / TTFT 实验

## 结论

本轮没有把视觉降采样接入正式 `performance` profile。原因不是“没有减少 Token”，而是
三个风险档位都没有同时通过双语 TTFT、吞吐和答案一致性门槛：

- 192-token 等效上限保持 400/400 解析答案一致，但英文配对 TTFT 中位仅
  `0.99803x`，没有形成双语稳定收益；
- 176-token 等效上限在中文 20 题中已有 1 题答案漂移，英文吞吐均值为
  `0.97959x`；
- 128-token 等效上限在中文 20 题中有 2 题答案漂移，且中英文吞吐均值均约
  `0.990x`。

因此正式 profile 继续显式 `unset SEU_VISION_MAX_PIXELS`，保持模型原始分辨率策略。

## 实验设计

模型与所有 PPU 扩展只加载一次；baseline 和 candidate 共用同一个模型，仅切换
`AutoProcessor(max_pixels=...)`。每个样本按 AB/BA 交替运行，记录：

- `image_grid_thw`、prompt token、合并后的 visual token；
- TTFT、去除 TTFT 后的吞吐；
- 完整文本哈希、解析答案、参考答案和正确性。

预设晋级条件为：真实减少视觉 Token；candidate Accuracy 不低于 baseline；保守阶段要求
每题解析答案一致；TTFT 配对中位和均值都大于 1；吞吐配对中位和均值都不低于 1。

Qwen3.5 视觉预处理的 patch size 为 16、merge size 为 2，因此一个送入语言模型的视觉
Token 约对应 `32×32=1024` 输入像素。`max_pixels=196608/180224/131072` 分别近似
192/176/128 个视觉 Token 上限。

## 分布扫描

中英文各取前 200 题，仅运行 processor：

| 上限 | 中文平均 Token | 中文变化题数 | 英文平均 Token | 英文变化题数 |
|---|---:|---:|---:|---:|
| 原始 | 172.400 | 0/200 | 154.315 | 0/200 |
| 192 | 167.500 | 15/200 | 145.355 | 24/200 |
| 176 | 160.470 | 61/200 | 137.420 | 79/200 |
| 128 | 113.910 | 178/200 | 104.920 | 143/200 |

192 档是稀疏触发的安全候选；128 档实际已平均削减约 25%--31%，属于明显的精度风险档。

## PPU 配对结果

### 192-token 档：安全但无稳定 TTFT 收益

中英文各 200 题、`max_new_tokens=64`：

| 语言 | Accuracy | 答案一致 | TTFT 中位/均值 | 吞吐中位/均值 |
|---|---:|---:|---:|---:|
| 中文 | 189→189 | 200/200 | 1.00141x / 1.00520x | 1.00469x / 1.00819x |
| 英文 | 154→154 | 200/200 | **0.99803x** / 1.00681x | 1.00245x / 1.00947x |

中文数字很小，英文 TTFT 中位为负；这更符合噪声级变化，不能当成可复现优化。

### 176-token 档：开始出现语义风险

中英文各 20 题筛查。中文答案一致 19/20、TTFT 中位 `0.99336x`；英文答案一致
20/20，但吞吐中位/均值为 `0.98385x/0.97959x`。门槛未过，未扩大长测。

### 128-token 档：风险和性能均不合格

中英文各 20 题。中文答案一致 18/20，TTFT 均值 `0.99012x`；英文答案一致 20/20，
但吞吐均值 `0.99037x`。降低更多 Token 没有换来稳定 TTFT，反而更早触发输出漂移。

## 为什么 Token 少了却没有明显更快

当前约 120 ms 的 TTFT 不只由语言序列长度决定，还包含图像预处理与搬运、视觉编码器、
首次算子/形状调度、语言模型 prefill 和运行时同步。192 档只改变 15/200 与 24/200 个
样本；128 档虽明显缩短序列，但新的图像 grid 形状也会引入调度噪声，而且视觉编码与
固定开销仍占主要部分。实验说明“限制 max_pixels”不是当前 PPU 路径的无损 TTFT 主杠杆。

脚本：


公开精简结果见 `results/ppu-visual-token-ab-20260901.json`。逐题 JSON 保存在本机
`artifacts/ppu-visual-token-20260901/`（gitignored），包括 processor 扫描、2/20/200 题
A/B 和每题哈希。服务器文件只作为本轮临时执行副本，不是工程唯一来源。

本轮同时在重启后的 PPU 实例实际执行了环境恢复：三类扩展重新编译成功；设备、GDN、
Linear、b/a-GEMV 符号与 packed-MLP smoke 全部通过。随后不使用任何手工 build 路径
覆盖，以正式 `performance` profile 运行样本 3000985，输出 B 与参考一致，且确认视觉
上限和首 Token cache 均关闭、b/a-GEMV 开启。冷启动 TTFT 只用于功能检查，不计入上述
性能统计。
